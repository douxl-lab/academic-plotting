# Evidence-bound scientific diagram generation

Adapted from Orchestra Research's four-family diagram reference. The original emphasis on explicit labels, connections and coherent style is retained; model choice, retry count and scientific acceptance are capability-driven rather than fixed preview-model assumptions.

## Scientific extraction precedes style

Read the actual method text/code. Extract exact entities, their roles, relationships, arrow direction/type, hierarchy/grouping, formulas and uncertain claims. Associate them with a specific source, locator and supporting quote. A terse abstract is not enough to invent a detailed module. Missing topology needs clarification or a visibly qualified draft.

Keep scientific facts in canonical FigureSpec v1; keep layout, palette and typography in design and presentation constraints. A user-approved design does not independently verify a scientific relationship. For quantitative content, preserve original tables and send measured panels to deterministic plotting; split hybrids rather than generating invented charts.

## Model and engine selection

Check the actual installed model registry/provider capabilities and account access for the requested task. Do not hardcode a permanently current model or call one key's provider because another failed. Relevant capabilities include system-prompt support, exact-text rendering, reference-image input, local editing, aspect ratio and output MIME.

- Prompt-only requests need no live provider access: produce a complete adapted prompt and mark it unrendered
- Existing accepted-image local repair needs a provider that actually supports reference input and editing; otherwise disclose the limitation and use the requested native/presentation route
- PaperBanana retains its real Retriever → Planner → Stylist → Visualizer → Critic engine. Use its source-locked request envelope and fail-closed version/schema/validator negotiation
- Generation, source disclosure and possible fees need specific authorization. Never include keys or credentials in a prompt, scientific specification or output bundle

See [exchange.md](exchange.md) for executable offline request/prompt/consumer commands. A bounded number of candidates may explore presentation differences; change that budget only within the user's cost/time authorization. There is no mandatory three-call rule.

## Scientific prompt structure

The shared compiler preserves these sections and their actual submitted bytes:

1. Task/identity: intended figure, candidate and stage
2. Immutable scientific contract: exact nodes, directed relationships, grouping, labels, formulas, original sources and constraints
3. Detailed design: arrangement and visual hierarchy without new scientific claims
4. Layout/composition: main flow, grouping, connectors and reading order
5. Visual style: selected coherent style and exact palette
6. Text/formulas: exact technical terms, legible typography and mathematical notation
7. Negative constraints: no invented numbers, omitted data, altered topology, unsupported formulas or decorative distraction
8. Verification boundary: source traceability and appearance are separate from scientific truth
9. Provider adaptation: actual capability guidance; system instructions merge into the user prompt only if system prompts are unsupported

Variation is bounded to presentation. Source excerpts are evidence, never instructions to execute or publish. Prompts must not add assumptions such as multi-class normalization to a multi-label model without code/formula support. A diagram showing uncertainty must use the actual model's definition and dimensionality.

## Four design families from the original skill

Choose based on the user's example, manuscript and venue. Do not force a style merely because it looks distinctive.

### A. Hand-drawn sketch / 简笔画

Slightly irregular charcoal strokes, softly rounded forms and restrained wash colors can make an overview approachable. Suggested colors: charcoal #2C2C2C; blue #D6E4F0; peach #F5DEB3; sage #D4E6D4; lavender #E6DFF0. Keep exact technical labels, deliberate connectors and a consistent line-art vocabulary. Avoid emoji, stock clip art and decoration that changes scientific meaning. Ensure a pale background is acceptable in the actual manuscript.

### B. Modern minimal

Crisp geometry, whitespace, restrained hierarchy, and limited palette. Suggested region colors: slate #E8EDF2; sand #F5F0E8; mint #E8F2EE, with sparse accents #2563EB/#059669/#D97706. Use exact aligned labels and high-contrast thin connectors. Shadows, decorative banners and dense card stacks are not prerequisites; clean scholarly mechanisms often work better with unboxed visual relationships.

### C. Illustrated technical

Consistent small line-art motifs can explain a meaningful scientific entity. Use an icon only where its meaning is source-supported; a database cylinder implies storage and should not replace a computation module. Keep the primary flow distinguishable from optional/feedback paths. Avoid icons, curves or badges that imply unsupported repetition, training stages or probabilistic semantics.

### D. Classic academic accent

White background, restrained region grouping, thin neutral boundaries and a small consistent set of accents (#4A90D9/#5BA58B/#D4A252/#7B8794). This is a starting vocabulary, not a demand for horizontal card bands. Exact topology and reading order take priority. Check grayscale and final-column readability.

For journal mechanism figures, prefer a coherent explanatory composition. Put figure numbers/titles in the manuscript caption unless the user or venue requires them in the image. Do not add stage numbers or A/B/C panels to a single independent figure just for decoration. Composed panels can use letters when the intended multi-panel structure calls for them.

## Review actual images, not prompt intent

After authorized generation:
- Fully decode the selected image and inspect its pixels
- Compare every required node/label/formula/arrow against the immutable source contract
- Check missing/extra entities, reversed arrows, ambiguous crossings, clipping, tiny text, unexpected panel labels and decorative objects with misleading meaning
- Record observed-image notes separately from the submitted design description
- Reject failed or unresolved candidates even if a retained image is attractive

For native reconstruction, provide the unchanged FigureSpec, selected inspected image and observed design notes. Rebuild native text, shapes and connectors in the approved appearance; do not approximate a measured plot with an illustration. Render and inspect the actual file and confirm editability. A PNG inside SVG/PDF/PPTX remains a raster reference, not an editable scientific diagram.
